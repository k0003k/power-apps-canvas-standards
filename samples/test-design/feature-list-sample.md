# 機能一覧サンプル

## 1. 機能一覧の位置づけ

機能一覧は、BFC初版で洗い出したシステム機能候補を、設計・実装・テスト可能な正式な機能単位として整理する成果物である。

```text
業務要件
  ↓
BFC 初版
  ↓
ユースケース間依存関係表
  ↓
機能一覧
  ↓
BFC 更新（正式な機能IDを紐付け）
  ↓
データフロー対応表
```

1つのBusiness Requirement（業務要件）に対して、BFC上で複数のシステム機能候補が存在してよい。

そのうえで、BFC初版の機能候補と、機能一覧の正式機能も1対1である必要はない。

この2つは別の関係として扱う。

```text
Business Requirement
   1 : N
BFC機能候補

BFC機能候補
   N : M
正式機能
```

機能一覧作成時または機能設計時に、統合、分割、共通化、責務変更が発生してよい。

## 2. 機能IDの体系

機能IDは、機能種別ごとの接頭語と連番で構成する。

| 機能種別 | 接頭語 | ID例 | 補足 |
|---|---|---|---|
| アプリ / UI | `UI` | `UI001` | 1キャンバスアプリを表す親管理単位 |
| 画面 | 親UI ID + 子番号 | `UI001-01` | `UI001`配下の1 Screenオブジェクト |
| インターフェース | `IF` | `IF001` | 外部システムとの1送受信機能。実装技術は問わない |
| バッチ | `BT` | `BT001` | 定期・一括・非同期で実行する1処理。実装技術は問わない |
| レポート | `RP` | `RP001` | 1帳票 |
| 共通 | `CM` | `CM001` | 1公開UDFまたは1公開メソッド |
| データ移行 | `MG` | `MG001` | 1移行先 |

画面の子番号は、文字列順でも正しく並ぶように2桁以上でゼロ埋めする。

```text
UI001
├─ UI001-01 申請入力画面
├─ UI001-02 申請履歴画面
└─ UI001-03 申請詳細画面
```

`UI001`はアプリ全体を表す親管理単位であり、画面の機能単体テスト対象は、原則として`UI001-01`以下のScreen機能とする。

`IF`と`BT`は実装技術ではなく責務で分類する。

- 外部システムとの送受信が主目的：`IF`
- 定期、スケジュール、一括または非同期処理が主目的：`BT`

## 4. BFC初版からの整理例

BFC初版では、例えば以下の機能候補が存在したものとする。

```text
申請入力
申請登録処理
外部申請送信
申請履歴確認
外部結果反映
申請承認
滞留申請確認
申請一覧帳票
申請データ移行
```

機能設計の結果、申請入力に含まれていた入力検証を共通化し、

```text
CM001 申請入力検証
```

として独立させてもよい。

この例では、`UC001`という1つの業務要件に対して複数のBFC機能候補が存在する。

さらに、そのBFC機能候補と正式機能も1対1でなくてよい。
例えば、BFC初版の「申請入力」に含まれていた入力検証を、正式設計では`CM001`として共通化している。

## 5. 作成・更新ルール

- 機能一覧は、BFC初版とユースケース間依存関係表を参照して作成する
- BFC初版の機能候補をそのまま機能IDへ置換するだけの作業にしない
- 設計・実装・テスト可能な責務単位として正式機能を整理する
- 必要に応じて機能候補を統合・分割・共通化する
- すべての正式機能に一意な機能IDを付与する
- 画面機能は親アプリIDを継承する
- IDは名称変更時にも原則として維持する
- 廃止したIDを別機能へ再利用しない
- 機能一覧確定後、正式な機能IDをBFCへ紐付ける
- 機能設計後に構成が変わった場合は、機能一覧を更新しBFCへ変更結果を反映する
- データフロー、Test Specificationおよび変更影響分析は、正式な機能IDを参照する
- 値が存在しない必須項目には、空欄ではなく`なし`または`－`を明記する

---

## 6. AI利用時の扱い

AIは、BFC初版から機能一覧を作成する場合、機能候補を機械的に1対1で正式機能へ変換しない。

責務、再利用性、実装方式、データフロー等を考慮して正式機能単位を提案する。

ただし、BFC初版の段階で明示されていない共通化・統合・分割を、根拠なく確定事項として扱わない。

変更影響分析やテスト生成を行う場合は、機能一覧を正式な機能ID・責務の管理元として使用する。

実装資産が機能一覧に存在しない場合は、推測で既存IDへ割り当てず、未登録機能として報告する。
